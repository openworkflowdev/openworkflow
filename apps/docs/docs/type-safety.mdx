title: Type Safety
description: End-to-end TypeScript type safety for workflows
---

OpenWorkflow uses schemas or explicit types to type workflow inputs and
outputs. Step result types are inferred from their functions' return values.
These types provide autocomplete and compile-time checking throughout.

## Schema Validation with Type Inference

For runtime validation with type inference, use [Standard
Schema](/docs/standard-schema) compatible libraries like Zod:

```ts
import { defineWorkflow } from "openworkflow";
import { z } from "zod";

const inputSchema = z.object({
  email: z.string().email(),
  amount: z.number().positive(),
});

export const payment = defineWorkflow(
  {
    name: "payment",
    schema: inputSchema,
  },
  async ({ input }) => {
    // input is typed as { email: string; amount: number }
    // and validated at runtime
    return { recipient: input.email, amount: input.amount };
  },
);
```

With a schema and no explicit generics, the input type comes from the schema
and the output type is inferred from the workflow function's return value.
Here, the output is `{ recipient: string; amount: number }`.

## Explicit Type Definitions

To manually specify input and output types, use both generics with
`defineWorkflow`. Generics provide compile-time checking; use a schema if you
also need runtime input validation.

This example uses your application's `validateOrder` and `shipOrder` functions.
Follow the [Quick Start](/docs/quickstart) for a runnable example with setup
instructions.

```ts
import { defineWorkflow } from "openworkflow";

interface OrderInput {
  orderId: string;
  customerId: string;
}

interface OrderResult {
  success: boolean;
  trackingNumber: string;
}

export const processOrder = defineWorkflow<OrderInput, OrderResult>(
  { name: "process-order" },
  async ({ input, step }) => {
    await step.run({ name: "validate" }, async () => {
      // input is typed as OrderInput
      return validateOrder(input.orderId);
    });

    const trackingNumber = await step.run({ name: "ship" }, async () => {
      return shipOrder(input.orderId);
    });

    // Return type must match OrderResult
    return {
      success: true,
      trackingNumber,
    };
  },
);
```

If you supply only the input generic, as in
`defineWorkflow<{ name: string }>(...)`, the workflow's output type is
`unknown`, so `handle.result()` returns `Promise<unknown>`. Supply both input
and output types when you need a typed result without a schema:

```ts
import { defineWorkflow } from "openworkflow";

export const greet = defineWorkflow<{ name: string }, string>(
  { name: "greet" },
  async ({ input }) => {
    return `Hello, ${input.name}!`; // Output checked against string
  },
);
```

## Workflow Specs

When using `defineWorkflowSpec` for separate declaration and implementation,
types flow through:

```ts
import { defineWorkflowSpec, OpenWorkflow } from "openworkflow";

// Declare the workflow spec with types
export const emailSpec = defineWorkflowSpec<
  { to: string; subject: string },
  { sent: boolean }
>({
  name: "send-email",
});

// Implementation receives typed input
const ow = new OpenWorkflow({ backend });
ow.implementWorkflow(emailSpec, async ({ input, step }) => {
  // input.to and input.subject are typed
  await step.run({ name: "send" }, async () => {
    await sendEmail(input.to, input.subject);
  });
  return { sent: true };
});
```

## Client-Side Type Safety

When you run a workflow, the handle is typed with the output:

```ts
const handle = await ow.runWorkflow(processOrder.spec, {
  orderId: "123",
  customerId: "456",
});

// result is typed as OrderResult
const result = await handle.result();
console.log(result.trackingNumber); // TypeScript knows this exists

const greetingHandle = await ow.runWorkflow(greet.spec, { name: "World" });
const greeting = await greetingHandle.result(); // string
```

## Step Result Types

Step return types are inferred automatically, even when you supply only the
workflow's input generic:

```ts
import { defineWorkflow } from "openworkflow";

interface User {
  email: string;
  name: string;
}

const workflow = defineWorkflow<{ userId: string }>(
  { name: "user-workflow" },
  async ({ input, step }) => {
    // user is inferred as User type from the return
    const user = await step.run({ name: "get-user" }, async () => {
      const response = await fetch(`/api/users/${input.userId}`);
      return (await response.json()) as User;
    });

    // TypeScript knows user has these properties
    console.log(user.email, user.name);
  },
);
```
